Origin Story

Why I built this

Content creation at scale is broken. Most teams either burn hours on manual research and drafting, or they publish low-quality AI slop with no editorial oversight. I wanted a third path.

I kept hitting the same wall: AI writing tools are powerful in isolation, but they chain nothing together. You prompt ChatGPT, copy the draft into a document, manually find sources, run it through Grammarly, paste it into WordPress, then schedule a tweet. Every step is a context switch. Every context switch is a chance to lose momentum or introduce errors.

The deeper problem is trust. Raw LLM output is not publishable. Hallucinated statistics, thin arguments, no keyword intent — without a review layer, you're gambling with your brand. But a fully automated pipeline with no human checkpoint is equally reckless.

So I asked myself: what would a senior content team look like if it ran as a software system? A researcher who fetches live sources. A writer who revises against critique. An editor who scores the draft. An SEO specialist who wraps it in metadata. And a human editorial director who makes the final call before anything goes public.

That mental model became this pipeline. LangGraph's interrupt() was the missing piece — it lets the graph pause at a well-defined checkpoint, surface exactly the right context to a human, and resume only on explicit approval. Everything before it is automated. Everything after it is irreversible. The line between them is the HITL gate.

I built it with production from day one: PostgreSQL checkpointing so runs survive crashes, SSE streaming so editors see tokens as they arrive, Prometheus metrics so you know which node is slow, and Kubernetes manifests so you can deploy it without drama.

The Research Gap
LLMs have knowledge cutoffs and confabulate. Real content needs live sources. This pipeline calls Tavily and Firecrawl on every run — no stale training data in your published articles.
The Quality Loop
A single pass through an LLM isn't enough. The Writer–Reviewer loop (max 3 iterations, scoring 0–10) catches weak arguments before a human ever sees them.
The Trust Problem
Full automation without oversight is reckless. The HITL gate is non-negotiable — it sits between "AI-generated" and "published", with no way to bypass it in code.
The Ops Reality
Demos are easy, production is hard. Crash-safe state via PostgreSQL, idempotent publishing via SHA-256 keys, and Kubernetes HPA ensure this runs reliably at any scale.
Provider Freedom
init_chat_model("openai:gpt-4o") means switching to Claude 3.5 Sonnet or Gemini is a one-line .env change — no refactoring required.

Architecture

How it's built

A stateful LangGraph graph sits behind a FastAPI service, persisting every node transition to PostgreSQL so runs are crash-safe and restartable from any checkpoint.

┌──────────────────────────────────────────────────────────────────┐
│                        FastAPI  (:8000)                          │
│  POST /runs  GET /runs/{id}/stream  POST /runs/{id}/resume   │
└──────────────────────────┬───────────────────────────────────────┘
                           │
                    ┌──────▼──────┐
                    │  LangGraph  │  StateGraph (interrupt)
                    │   Pipeline  │
                    └──────┬──────┘
          ┌────────────────┼────────────────┐
          │                │                │
    ┌─────▼─────┐   ┌──────▼──────┐  ┌─────▼──────┐
    │ Ingestor  │   │ Researcher  │  │  Writer    │
    │ (parse)   │   │ (Tavily +   │  │ (GPT-4o /  │
    └─────┬─────┘   │  Firecrawl) │  │  Claude)   │
          │         └──────┬──────┘  └─────┬──────┘
    ┌─────▼─────┐          │         ┌─────▼──────┐
    │  Planner  │          │         │  Reviewer  │
    │ (outline) │          │         │ (score ≤3x)│
    └───────────┘          │         └─────┬──────┘
                           │               │
                    ┌──────▼───────────────▼──────┐
                    │         Optimizer            │
                    │      (SEO + metadata)        │
                    └──────────────┬───────────────┘
                                   │
                    ┌──────────────▼───────────────┐
                    │      HITL interrupt()         │  ← React UI
                    │  Human approves / rejects     │
                    └──────────────┬───────────────┘
                                   │
                    ┌──────────────▼───────────────┐
                    │         Publisher             │
                    │  WordPress · LinkedIn · X     │
                    └───────────────────────────────┘

  Storage: PostgreSQL (AsyncPostgresSaver) + Redis cache
  Observability: LangSmith · Prometheus · Grafana
Durable State
Every node transition is checkpointed to PostgreSQL via AsyncPostgresSaver. A crashed pod resumes from the last checkpoint — no work is lost, no duplicate publishes.
SSE Streaming
GET /runs/{id}/stream emits token-by-token events via Server-Sent Events. The React HITL UI shows live generation so editors aren't staring at a spinner for 30 seconds.
Idempotent Publish
A SHA-256 hash of the content serves as an idempotency key. Retrying a failed publish never creates a duplicate post on WordPress, LinkedIn, or X — a critical guarantee in distributed systems.
Features

What's included

Every component was built for production, not demos. No placeholder nodes, no stub implementations.

01
Multi-Agent StateGraph
7-node LangGraph 1.0 StateGraph with typed ContentState, conditional edges, and a Writer↔Reviewer loop that runs up to 3 revision cycles.
02
HITL Interrupt Gate
LangGraph's interrupt() halts execution before publish. The React UI surfaces the draft, SEO score, and outline. Approve, reject, or add feedback — then POST /resume.
03
Live Research
Tavily web search returns ranked results with recency filtering. Firecrawl deep-scrapes selected URLs. Sources are attached to every draft so HITL reviewers can verify claims inline.
04
Provider-Agnostic LLM
Uses LangChain's init_chat_model — a single string like "anthropic:claude-sonnet-4-5" in .env swaps the underlying model with no code changes.
05
SEO Optimizer
Structured output via Pydantic produces slug, meta description, Open Graph tags, and a keyword density score. No free-form strings — every field is validated before it reaches the publisher.
06
JWT Auth + Rate Limiting
POST /token issues Bearer tokens via python-jose. slowapi enforces per-IP limits on /runs to prevent abuse. All endpoints require auth except /metrics.
07
Full Observability
Prometheus histograms on every node (p50/p95/p99 latency), LangSmith traces for LLM calls, Loguru JSON logs, and a pre-built Grafana dashboard with 5 alert rules including a dead-man switch.
08
Kubernetes-Ready
HPA scales API pods 2→10 replicas at CPU 70%/mem 80%. Pod anti-affinity spreads replicas across nodes. The Ingress is configured with SSE-aware timeouts so streams don't get cut off.
09
74 Async Tests
pytest-asyncio suite covers ContentState validation, every node's happy path and error paths, router logic, and all API endpoints using httpx.AsyncClient(ASGITransport).
Upgrade Insights & Future Vision

Where this goes next

The foundation is production-solid. Here's the upgrade path — from immediate enhancements to the longer-term vision of a fully autonomous content intelligence platform.

Phase 1 — Near Term
Smarter Content
  • RAG Memory Layer — pgvector index of past articles prevents duplicate coverage and lets the Writer reference prior work for internal linking.
  • Tone Profiles — per-client voice configuration (formal/casual/technical) stored in PostgreSQL and injected at the Writer node as a system prompt preamble.
  • Multi-format Output — extend Publisher to produce LinkedIn newsletters, Twitter threads, and email digests from the same approved draft.
  • Source Quality Scoring — rank Tavily results by domain authority and recency before passing to the Writer, reducing citations from low-credibility sources.
  • Fact-Check Node — a dedicated post-write agent that verifies numeric claims and proper nouns against a second search pass before the HITL gate.
Phase 2 — Medium Term
Autonomous Intelligence
  • Topic Discovery Agent — monitor SERP gaps and trending queries; automatically propose new content briefs to a human approver queue.
  • Competitor Analysis — Firecrawl competitor sites nightly, extract topic coverage maps, and surface whitespace opportunities in a Grafana panel.
  • Performance Feedback Loop — pull GSC/GA4 metrics post-publish and feed them back into a fine-tuned Planner that learns which outlines drive engagement.
  • Image Generation — integrate DALL·E or Stable Diffusion for auto-generated featured images with Alt text from the Optimizer node.
  • Multi-Language Pipeline — a Translation node after Publisher dispatches localised versions to country-specific WordPress multisite instances.
Phase 3 — Long Term
Platform Vision
  • Self-Improving Prompts — DSPy-style automatic prompt optimisation using historical review scores as a training signal. No manual prompt engineering.
  • Multi-Tenant SaaS — row-level security in PostgreSQL, per-tenant model configs, usage-based billing via Stripe, and a Next.js dashboard replacing the React HITL UI.
  • Agentic Content Strategy — a meta-agent that reads analytics, allocates budget across content types, and schedules pipeline runs — replacing a human content strategist for routine decisions.
  • Fine-Tuned Models — LoRA fine-tuning on approved content corpus for brand-voice consistency without system-prompt injection at every call.
  • Real-Time Personalisation — per-reader content variants generated on-request using edge inference (Cloudflare Workers AI) fed by a reader interest model.

Architectural Upgrades Worth Considering Now

Replace Redis cache with Valkey
Valkey (Redis fork, fully open-source) drops the BSL licensing concern and is a drop-in replacement. Worth the switch for any commercial deployment.
Move to LangGraph Cloud
LangGraph Cloud manages the PostgreSQL checkpointer, SSE infrastructure, and horizontal scaling automatically — offloading the ops burden while keeping the same graph code.
Add a Message Queue
Replace the direct FastAPI→LangGraph call with a Celery or ARQ task queue backed by Redis Streams. Decouples HTTP response time from graph execution time and enables priority queues.
Streaming to WebSockets
SSE is one-directional. Upgrading to WebSockets enables the HITL UI to send inline annotations mid-stream — editors can flag specific sentences for revision before the draft finishes generating.
Structured Evals Framework
Integrate LangSmith Datasets to run regression evals on every graph change. Track review_score distributions and HITL approval rates as CI quality gates — no more shipping blind.
CMS Connector Abstraction
Extract the Publisher into a pluggable connector interface — CMSConnector base class with WordPress, Ghost, Webflow, and Contentful implementations. New platforms in <50 lines.

Quick Start

Up and running in 5 minutes

1
Clone and configure
# Clone the repo
git clone https://github.com/SaiAle/ai-content-engine.git
cd ai-content-engine

# Copy the env template and fill in your keys
cp .env.example .env
2
Set required environment variables
# Minimum keys to get started
PRIMARY_MODEL=openai:gpt-4o
OPENAI_API_KEY=sk-...
TAVILY_API_KEY=tvly-...

# Optional: swap the reviewer to Claude
REVIEW_MODEL=anthropic:claude-sonnet-4-5
ANTHROPIC_API_KEY=sk-ant-...

# Publishing targets
WORDPRESS_URL=https://yourblog.com
WORDPRESS_APP_PASSWORD=xxxx xxxx xxxx
3
Start services with Docker Compose
docker compose up -d
# PostgreSQL :5432 · Redis :6379 · API :8000
4
Run your first content pipeline
# Get an auth token
TOKEN=$(curl -s -X POST http://localhost:8000/token \
  -d "username=admin&password=secret" | jq -r .access_token)

# Kick off a content run
curl -X POST http://localhost:8000/runs \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"topic":"The Future of AI Agents","content_type":"blog_post","target_platform":"wordpress"}'

# Stream the output live
curl -N http://localhost:8000/runs/{thread_id}/stream \
  -H "Authorization: Bearer $TOKEN"
5
Approve at the HITL gate
# The pipeline pauses here — review the draft, then resume
curl -X POST http://localhost:8000/runs/{thread_id}/resume \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"approved": true, "feedback": "Looks great — publish it."}'
API Reference

Endpoints

All endpoints require a Bearer token obtained from POST /token, except GET /metrics.

Method Endpoint Description Response
POST /token Exchange username + password for a JWT Bearer token. { access_token, token_type }
POST /runs Start a new content pipeline run. Returns immediately with a thread_id — graph runs asynchronously. 202 { thread_id }
GET /runs/{id} Snapshot of the current ContentState for a run — useful for polling or debugging. ContentState
GET /runs/{id}/stream Server-Sent Events stream of graph events and LLM token deltas. Keep the connection open until the HITL interrupt fires. SSE stream
POST /runs/{id}/resume Resume a run paused at the HITL gate. Body: { approved: bool, feedback?: str }. Resumes graph execution and triggers publish. 200 OK
GET /metrics Prometheus text-format metrics. Scraped by Prometheus every 15s. Includes per-node latency histograms and token cost counters. text/plain
